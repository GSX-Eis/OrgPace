# ADR-0026：按组织架构自动代理审批（原限时代理审批）

## 2026-11-26 更新（NERE-1426）：改为按组织架构实时自动代理

1. **取消手动设置代理**：`POST/DELETE /orgs/{org_id}/me/review-delegations` 统一返回 `410 Gone`，前端「设置 → 偏好与代理 → 代理审批」改为只读展示当前用户的自动代审上级列表与规则说明。保留 `review_delegation` 表以保存历史记录，但不将其用于实时权限计算。
2. **动态实时计算全部组织上级**：给定申请员工经 `_assignment` 得到主审批人列表与命中的部门 `matched_department_id` 后，自动代审人集合为以下两路去重并集：
   - **路径 A（全层级汇报线祖先）**：从主审批人绑定的员工出发，沿当前有效汇报线（`ReportingLine.valid_to IS NULL`）逐级向上追溯至根（带 `visited` 防环）；链上所有在职且拥有同企业启用 `User` 账号的成员均可自动代审（中间节点无账号或停用不阻断继续向上追溯）。
   - **路径 B（严格上级部门的全部部门经理）**：若 `matched_department_id` 非空，沿部门树向上追溯严格高于 `matched_department_id` 的所有祖先部门（带 `visited` 防环，避免跨分支部门经理越权），收集全部在职且账号启用的 `DEPT_MANAGER` 用户。
   - 严格排除申请员工本人（不可自批红线）、主审批人本人（直接审批不记代理）、非本企业/停用账号/离职员工。
3. **统一入口与最小可见范围**：`can_review` / `reviewable_employees` / `can_review_any` 为画像、负荷、延期、机器人与 MCP 的唯一判定入口。非管辖纯汇报线上级不扩大日常员工与证据可见范围，仅在请求 `PENDING_REVIEW` 期间通过 `review_access` 获得请求级临时读取权限；在此临时读取权限下，审批页与证据详情仅返回本单待审项送审能力与该证据的关联，不暴露同一证据在员工画像中关联的其他能力项。审批完成、撤回、汇报线变更、部门调整或角色/账号停用后立即回收。
4. **通知与审计口径**：
   - 新提交画像请求、负荷调整申请、延期申请时，收件箱与 IM 通知仅发送给主审批人，避免向全部隔级上级群发；所有组织上级仍可在「协同 → 待审批」及机器人/MCP 中查看并代审。
   - 当上级实际代审提交决定（`acting_for_user_id` / `decided_for_user_id` 非空）时，保留实际审批人与被代表原审批人记录，审计日志 `details` 额外写入 `"acting_for_user_id"` 与 `"delegation_mode": "org_hierarchy"`，并向被代表的原审批人发送一条站内通知回告结果。

---

## 原设计背景（保留历史表结构参考）

原方案曾支持经理为本人设置同企业启用成员作为限时代理，使用 PostgreSQL 自带的 `btree_gist` 扩展和排斥约束保证并发写入不重叠。保留 `review_delegation` 表及历史迁移以兼容已有历史记录，降级/升级约束不变，不新增 Python 或前端依赖。

2026-11-11 补充（NERE-305）：凭待审批请求读取证据时，审批页与证据详情页都按同一次 `review_access` 结果展示关联判断。例外只覆盖该请求主体员工的判断及其证据，不扩大到同一证据关联的其他员工。请求已处理或上级权限回收后仍回到原有可见范围，restricted 正文沿用既有规则。

2026-11-26 补充（NERE-1433 / D-087）：进一步收窄仅凭待审批请求获得临时读取资格时的证据关联范围。对于无日常员工可见范围（`employee_scope_clause` 不命中）的临时代审人，审批页（`get_review`）和证据详情（`read_evidence`）的 `claims` 字段仅返回本单待审改动项所送审能力与该证据的关联，不再列出同一证据在员工画像中关联的其他未送审能力项；具备日常管辖权的经理、员工本人与企业管理员仍按既有服务端 `Principal` 规则查看。请求审批完成、撤回或组织架构/角色/账号状态变更后，临时权限立即回收。
