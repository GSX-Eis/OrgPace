# 经理使用指南

容量与协调方案操作已按 M8 更新；画像截图保留 M4.3 的界面，操作以文字说明为准。

登录后从「待审批」或收件箱进入请求。默认只显示当前由你处理的请求，部门范围包含获授权部门的全部下级部门。本人请求交上级部门经理或企业管理员，管理员与代理人也不能自批。

正式画像通过两种方式改变：经理批准请求（关闭经理确认的能力类别由本人确认后发布为「暂定」），或企业管理员、管辖经理直接修改他人画像并通知本人（E21）。系统自动起草仍先交本人过目；任何人不能批准自己的请求，也不能直接改自己的画像。

## 谁能看到我的画像

| 内容 | 谁能看到 |
| --- | --- |
| 正式画像的能力、等级、状态和陈述 | 本人、管辖经理（含获授权的上级部门经理）、企业管理员 |
| 依据说明和受限自述正文 | 本人和管辖经理；经理在网页审批页查看 |
| 请求中未发布的陈述（含待本人过目、待审、退回等） | 本人、管辖经理；当前实际审批人及有效代理在待审批期间可读该请求 |

管辖范围包括获授权部门及全部下级部门，直属上级关系本身不授予部门权限。管理员身份本身不能读受限正文，兼任本人或管辖经理时按该身份授权。助手工具不提供下属的依据、受限正文和来源，需到网页审批页查看。查看不通知本人，也不留应用内查看记录；直接修改发布后通知本人。代理审批的临时读取例外见下文。

以上为在职员工规则。企业管理员如果既不是本人、管辖经理，也不是该待审请求的实际审批人或有效代理，不能读未发布的陈述；部分批准只放行已批准项，其余仍隐藏。草稿仍由员工本人编辑、提交。

离职员工的画像和自述归档只读，经理、本人和其他非管理员均不可见，也不再出现在团队及助手、飞书、MCP 的团队查询中。只有企业管理员可看归档的能力、等级和状态；受限自述和经理评价正文即使管理员兼任部门经理也不显示。离职时账号停用，未处理请求自动撤回，不能继续审批；恢复在职不会自动恢复这些请求。

数据保存在本企业自己部署的服务器上；存放位置、备份和保留期限请问企业管理员。

## 助手与我的团队

登录后进入三栏助手界面：图标导航、会话列表、对话区。导航包含聊天、收件箱、待审批、我的画像、我的团队和组织架构，底部是设置。模型不可用时，手工页面仍可用。本人画像编辑、材料上传及设置内容见[员工指南](employee-guide.md)。

「我的团队」列出服务器允许查看的人员，包含获授权部门及全部下级部门；列表和手机卡片都显示工号，下属画像标题也显示工号，同名时先核对。「初始画像」列区分等待工作记录、等待起草、待本人过目、未生成判断、「本人已过目」和「经理或管理员已直接修改」等状态；直接修改不代表员工已过目，仅提交本人补充也不算初稿已过目，是否发布仍看审批状态。兼任企业管理员时从「员工」查看同一列。本人档案（含工号）、Jira 账号、自动起草等移到设置，下属档案仍由管理员维护。

点击下属画像的能力名称先打开「能力详情（只读）」，展示完整陈述、等级、状态和北京时间的最近更新时间；依据和来源在网页审批时查看。需要改动时再点独立的「直接修改」。未定级的已发布判断显示陈述摘要，单列「未定级」，不计入「已确认」项数；结合陈述辨别否定和仅协助的含义。

词典缺少能力时，可在「添加能力」搜索无结果后「建议新增这项能力」，以你本人的身份建议，不会替下属修改画像。也可在网页或飞书助手中先核对建议内容并明确同意，交管理员处理；每人最多五条待处理。超时、附件复用、未保存输入保护和底部「退出登录」用法与[员工指南](employee-guide.md)一致。

### 切换界面语言

平台默认使用中文界面（`zh-CN`），支持在登录页和主界面顶栏右侧直接点击 `中文 / EN` 一键切换，无需进入二级菜单。切换后立即写入浏览器本地缓存并同步保存到当前账号偏好，刷新或更换设备登录后自动恢复。待审批页面、站内通知（历史通知若无英文仍显示中文）、后端报错、IM 推送及内置助手回复均跟随当前界面语言；员工姓名、部门名称、能力词典和证据原文等业务数据保持原文展示。

## 按能力找人

从导航「找人」进入「按能力找人」（`/find-people`）。只有部门经理和企业管理员可用：经理查询获授权部门及全部下级部门的在职员工，管理员查询本企业在职员工。直属上级关系和临时代审不会扩大找人范围。

1. 选择「能力（必选）」，按需选择「最低等级」和「部门（含下级）」。等级顺序采用这项能力的词典等级说明。
2. 可选「判断状态」、最近证据起始／结束日期；状态不选则不限。企业启用时，还会显示岗位序列、工作地点、入职起始／结束日期。
3. 勾选「只看把这项能力列为对应能力的部门」可按部门对应能力限制结果，包括从上级部门继承的能力。
4. 点「查找」，核对结果中的陈述、等级、状态、证据数、最近证据时间、批准人和批准时间，点员工姓名进入画像。

按最低等级筛选时默认不匹配未定级的判断；勾选「包含未定级」后仍会包含这些已发布陈述。没有设置最低等级时，未定级判断本来就可匹配。最近证据时间只计算仍有效的证据。找人结果不提供证据标题、原文、依据说明或受限正文，需要审批依据时到有权访问的网页审批页查看。

工作反馈形成的能力判断发布后也可以找到。反馈本身不计入证据数、最近证据日期、日期筛选或同等级排序。如果新人只有这类证据，按能力可找到，设置最近证据日期筛选时可能查不到。

**未知不等于不会**：没有已发布判断的人不会出现在结果里，查不到不能据此认定员工不会；只有 Jira 支持的判断最多为「暂定」。找人只提供只读信息，不判断空闲时间，也不发起调配或用于绩效评分。

### 在内置助手中找人

网页或飞书的员工／经理助手可以接受「找最近十二个月有证据、能独立完成某项工作的人」这样的请求。说明能力、最低等级、时间范围等条件，核对助手返回的陈述和状态，再打开画像链接。此助手只按部门经理管辖范围找人，普通员工不能借它查询团队；只有企业管理员身份、没有部门管辖授权时，也不能使用此助手的找人工具。管理员查询全企业请用「找人」页。

网页或飞书内置助手和「找人」页共用筛选和权限规则；管理助手的职责仍是企业管理，找人请用「找人」页或员工／经理助手。外部 MCP 入口默认关闭。

## 需求与容量

企业管理员在「能力与规则 → 需求与容量」开启后，导航才出现「需求与容量」（`/capacity`）。其中有「我的负荷」「我的分配」「待我审批」「团队负荷」「我提的需求」「收到的需求」，按本人身份显示。关闭模块后入口和工具消失，记录保留，画像不受影响。

下文 A 是提需求的部门，B 是承接部门。经理的管辖范围包含获授权部门及其全部下级部门。部门档期评估供选择部门时参考，正式排期由 B 方确认。

### A 方：提需求和确认替代排期

1. 进入「规划 → 需求与项目 → 已发出的需求」，点「新建需求」。选择需求方部门、能力和可选的最低等级，填写期望起止日期和需求说明。普通员工代表本人所在部门提交，经理可在管辖范围内选择需求方部门。
2. 点「评估承接部门」，查看哪些部门能在指定日期承接、最早何时能开始，或暂不可承接。选择一个目标部门。人数、每人投入和每周安排由目标部门经理决定。
3. 点「预览需求」，核对部门、任务目标及时间窗，再点「确认提交需求」。如用网页或飞书助手起草，说明任务目标和时间窗，核对确认卡后提交。

收到通知后，从「已发出的需求」打开详情。需求方可以看到正式起止日期、阶段排期和部门级状态，执行人和个人投入只向有权限的承接方显示。

| 状态 | 可以做什么 |
| --- | --- |
| 待目标部门确认 | 等待经理排期，或撤回需求。旧口头答复也在此等待正式排期 |
| 已接收 | 查看已生效的起止日期和各阶段排期 |
| 待确认替代排期 | 核对日期和暂留截止时间，在 72 小时内点「确认排期」或「放弃」。放弃时选择原因并填写说明 |
| 已拒绝 | 查看拒绝结论，可追问或撤回需求 |
| 已撤回 | 查看历史记录 |

提议人不能确认自己的提议。借调还须原部门经理和员工本人同意。

### 跨部门项目：逐角色提需求

1. 到「需求与容量 → 项目需求」，点「新建项目需求」。填项目名称、需求方部门和可选的项目说明。
2. 为每个角色填名称、工作说明、主能力和时间窗口。评估档期后选择目标部门。可为能力选择最低等级，每个角色最多再加五项不同的额外能力。勾选「必需」表示承接人须达标，未勾选的能力在候选人余量相同时作为优先参考。
3. 用「添加角色」继续，最多十二个角色。如果后面的角色要等某角色完成，先填写前置角色，再在后面的角色勾选它。一个角色只能发给一个部门，需要两个部门出人时拆成两个角色。
4. 点「提交项目需求」。如果提示某角色的额外能力或最低等级失效，刷新后从现行词典重新选择，核对其余角色再提交。校验通过后，各目标部门分别排期。A 方从项目页查看各角色状态和阶段日期，必要时打开角色详情确认替代排期。

也可在网页助手说明项目、各角色的部门、能力、日期和依赖关系，核对「项目草稿」，点「确认创建项目」。飞书助手发来摘要和链接时，打开链接登录网页，再确认创建。

项目页的「分阶段时间表」显示各角色的计划日期、受前置角色约束的最早开始及预计日期。「项目影响」提示哪些后续角色受阻或预计推迟。各目标部门可从自己的角色需求打开项目摘要。A 方看到部门级时间表和影响，B 方人名及个人负荷只在有权查看的部门页面显示。要追问或撤回时，打开各角色需求查看当前可用的操作。

### B 方：打开收到的需求

进入「待审批 → 协作需求」，核对能力、期望时间和说明。目标部门管辖经理或企业管理员可以代表 B 方排期。符合排期条件的旧口头答复会标为「旧答复待排期」，打开后点「生成/调整内部方案」即可继续。新需求无法承接时，从「拒绝需求」选择原因并填写部门级说明。说明里避免写员工姓名和负荷情况。

### 查看决策记录和拒绝原因

打开角色或单部门需求详情的「决策记录」。这里可以查看历次提议、各方审批和「需求时间线」。有权的 B 方还可展开「历史方案结论」。新拒绝从「人手或余量不足」「能力不匹配」「时间不合适」「与其他工作冲突」「需求不清或范围变化」「其他」选择，选「其他」须说明。历史未填分类的拒绝显示「未分类」。员工本人不同意借调的理由仅本人可见。

### B 方：生成、读懂和修改协调方案

在需求详情点「生成/调整内部方案」，查看部门成员能力、各周负荷和方案中的投入、日期。只有有权代表目标部门的经理或管理员能进入，A 方和普通员工不能查看 B 方的人员方案。方案页不依赖模型。

方案类型包括「直接安排」「安排新人」「推迟交付」「缩小范围」「分阶段交付」「向其他部门借调」「自定方案」。结论显示「可行」「有条件可行」「不可行」「数据不足」；「数据不足」不能当成有空，先核实或确认周容量。每张方案都有交付日期、覆盖人数、缺口（人周）、人员投入和日期、「受影响的工作」「风险」「条件」及「需要谁确认」。选中具体方案后，确认表单会提示是否需要需求方确认。借调仍须相关部门同意。

如果列表出现「优化方案」，可以和规则生成的方案比较。点「调整投入分段」可调整人员、投入比例和各段起止日期，然后重新模拟。

在「快捷修改」一次只改一个条件，再点「确认修改」：

| 按钮 | 怎么用 |
| --- | --- |
| 换人 | 选「人员」和「换成」的候选人；只能选当前快照里有权查看且尚未选用的人 |
| 锁定／解锁 | 选定人员；锁定后不能换掉或改变其时间、投入，需先解锁 |
| 改时间 | 选一人或「所有未锁定人员」，填新的开始、结束日期 |
| 降低投入 | 选一人或所有未锁定人员，填投入比例；仍须看需求缺口和确认条件 |
| 分阶段交付 | 填第二阶段开始日期（周一）；有锁定人员时先解锁 |

修改会在同一份数据快照上重新校验，新增「自定方案」，原方案保留。「这次改了什么」列出结论、日期、覆盖人数、缺口和新增／解决风险的前后差异。锁定只约束方案编辑。

旧快照可能因升级后的容量口径变化或之后的数据变动而失效。看到「数据已变化，请重新模拟」时，点「重新模拟」读取最新数据，再核对安排并选方案。

### B 方：确认生效或提交替代排期

1. 点「按此方案答复」，核对日期并写部门级答复说明。排期完全在需求方时间窗内且无需借调时，点「确认方案并生效分配」，需求变为「已接收」，页面跳到「部门内分配」。
2. 超出时间窗或涉及借调时，点「提交替代排期」。暂留期限为 72 小时。待确认期间可以「撤回提议」，需求方也可以「放弃」。过期、撤回、放弃或容量复核失败后，暂留释放，可点「重新规划」。
3. 如提示某周投入超出可用比例，先核对该周容量，或调整人员和日期后重新模拟。

### 借调：B 方提议，原部门经理选人

1. B 方在「向其他部门借调方案」选择「借出部门」，点「按此方案答复」，核对说明后点「提交替代排期」。
2. 原部门有权经理进入「需求与容量 → 借调请求」，核对借入部门、日期和投入，在「借调员工」选人，点「确认人选」。此时才开始为选中的员工预占，提议的到期时间沿用发出时的时间。页面显示「已安排人员，等待本人同意」。如不能承接，选择「拒绝原因」并填说明后点「拒绝借调」。
3. 员工在「我的分配」处理借调请求，A 方在需求详情点「确认排期」→「确认接受」。只有原部门经理、员工本人和 A 方都同意后，借调才随方案生效。本人不同意后，其他人只看到「借调未达成」。借调生效后，B 方在「部门内分配」看到「借调 1 人」及投入、日期和状态，部门归属、直属上级和画像审批关系保持原样。

### 已生效安排：发起和确认变更

1. B 方在需求详情点「发起变更」，按最新数据模拟。要换人或调整投入、日期时，可点「调整投入分段」，编辑后点「模拟调整后的安排」。
2. 在新的方案卡点「按此方案变更」，填写「变更理由」，再点「发送变更提议」。等待 A 方处理期间，原分配继续生效。
3. A 方打开「安排变更提议」，核对「变更前」与「变更后」的起止日期和阶段排期。同意时点「接受变更」→「确认接受」；拒绝时点「拒绝变更」、选「拒绝原因」并填说明后点「确认拒绝」。新增借调还须原部门经理选人和本人同意。
4. 生效后，B 方在「部门内分配」核对新分配，原来被替换的分配显示「已取消」。拒绝、过期或复核失败时，原安排和承诺日期保留。推迟完成日期仍走下文的延期流程。

### B 方：用协调助手调查与准备答复

可以在网页或飞书助手说：「看看这条需求，本部门按期交付有哪些方案？比较直接安排和安排新人，先不要发答复。」助手按你的身份读取需求、容量和候选人，模拟、校验和比较；缺少的信息影响决定时再追问。

经理的方案卡显示「交付日期」「覆盖人数」「缺口」「人员」「受影响的工作数」「风险」「审批人」；数字来自服务端方案。网页点「在方案页修改」可进入对应需求的方案页，飞书显示方案文字和页面链接。推荐结论比规则方案差时，卡片还会展示「规则引擎方案」和差别，网页可点「查看规则引擎方案」对照。A 方只能得到部门级结论，普通员工不会因此获得 B 方人员名单。

选好后可说「按这个方案准备答复，说明只写部门能否承接、日期和条件」。核对助手的提议确认卡，点「确认」才发送。窗内且无需借调的方案确认后直接生效。超窗或借调的方案等待需求方确认。已生效安排的变更在网页发起和确认。

决定「暂时不能」时，请让助手按普通答复准备并给出拒绝原因，再核对确认卡。比较方案卡仍可打开推荐和规则方案查看差别。

模型、超时或工具失败时，按提示点「前往收到的需求」，回到需求详情生成并确认内部方案。经理角色撤销、管辖部门集合收窄或模块关闭后，原会话中已失去权限的助手回复会隐藏，继续对话重新读取当前权限内的数据；旧卡片不能保留已失去的操作权。

### B 方：部门内分配和完成日期

按方案生成的分配可在「收到的需求 → 查看详情 → 部门内分配」查看。要调整已承诺段的开始日期，有权发起变更的经理可以点该行的「发起开始日期变更」，在「协调方案」中用「调整投入分段」修改日期并发出变更提议。A 方接受后，新日期和周投入才生效。换人、增减人员、改投入和提前结束也走正式变更。

历史上已接受且没有方案的旧需求，仍可在同一页面手工安排：

1. 在「新增分配」里「从依据中选择员工」，填写「投入比例（%）」（10%–100%）、必填的「开始日期」和「预计完成日期」，点「确认分配」。开始日期不得早于承诺开始日期，也不得晚于预计完成日期；初次分配的完成日期不得晚于当前承诺完成日期。同一需求同一人只能有一条进行中的分配。若所选员工提交时已离职，有权经理会看到「该员工已不在职，请刷新后重新选择」，候选人列表也会刷新。
2. 候选分为「依据中的员工」和「本部门其他在职员工（不在依据中）」，均须是 B 方范围内、本人有权查看的在职员工。选后者须勾选「该员工不在依据中，我确认按自己的判断安排」；这不会更改画像、依据人数或 A 方看到的内容。
3. 进行中的手工分配可「标记完成」或「取消分配」，结束后投入不再计入负荷。在「修改开始日期」填「调整后的开始日期」并点「保存开始日期」，或在「修改完成日期」填新日期并点「保存完成日期」。旧分配可能显示「开始日期未确认」。日期改动会通知员工，已结束的分配不能修改。
4. 若进行中的分配属于已离职员工，B 方有权经理看到的姓名固定为「已离职员工」，仅可点「取消分配」。页面隐藏「标记完成」和日期修改，取消后从列表消失；A 方仍看不到该员工的身份和分配。

新建分配、修改开始或完成日期、同意延期都会校验从开始周与本周较晚者到结束周的容量；过去的周不再校验，结束日期早于本周时跳过。任何当前或未来周「未确认」「需重新确认」或投入超出可用比例，服务端返回 409；错误区列出受影响周、状态或超出比例，并提供「去确认团队负荷」链接。先请经理确认这些周或调整安排后再提交，没有越过校验的开关。记录现实的设置周投入、登记不可用日期仍可进行，即使因此显示超额，已有分配也不会自动调整。

### 跟踪任务与人员不可用

- 正常分配从「收到的需求 → 查看详情 → 部门内分配」打开进行中分配的「任务跟踪」。原部门经理跟踪借调时，从「借调请求 → 进行中的借调分配」找到本人仍有权管辖的员工。输入「任务编号或标题」，点「搜索任务」，确认结果后点「关联任务」，选错可点「取消关联」。任务应已从 Jira 同步或 CSV 导入。
- 跟踪显示「未关联任务」「任务进展正常」「关联任务已全部完成，可以结束分配」「任务逾期」或「任务已交接」。状态变化会提醒承接部门经理，提醒可从收件箱打开对应需求和方案。借入方从分配列表看匿名进度，A 方在有延期风险时看部门级提示。
- 登记不可用日期与进行中分配重叠时，承接部门经理收到影响天数的提醒，项目角色还可能有受影响的下游和预计推迟天数。可沿提醒打开方案页「重新模拟」或「发起变更」。原人员、投入和承诺保留，变更须经原有审批。

### 为已完成的分配写工作反馈

有员工管辖权的经理或企业管理员可在「部门内分配」的已完成分配点「写反馈」。原部门经理也可在「借调请求 → 已结束的借调分配」操作。

1. 填写 20～500 字，描述完成的工作和可核实的结果。选择相关能力，表单预选角色的主能力和必需能力。反馈只记录事实，不打分。
2. 点「发送给员工过目」。每条分配最多一条有效反馈，不能给自己写。需求方看不到反馈正文。
3. 等员工过目并提交后，在「待审批」处理需要经理确认的能力。企业关闭该能力的经理确认时，本人提交后直接发布为「暂定」。如已发出的反馈需要更正，按证据更正流程处理。

### 延期审批与对外承诺

员工在「我的分配」申请延期，表单和提交结果显示审批人姓名；无人能审批时提示联系企业管理员。也可在助手里说明新日期和原因、核对后确认提交。经理在「需求与容量 → 待我审批 → 延期审批」看当前完成日期、申请完成日期、对外承诺和原因，选择「同意」或「退回」；退回必须填「处理说明」，再点「同意延期」或「退回延期」。

审批沿用当前审批路由，任何人不能批自己的申请。延期的审批人和自动代审上级还必须是 B 及其下级部门的在职成员，或 B 的有权代表（管辖经理或企业管理员）；跨部门的纯汇报线上级不能代替 B 审批或读取 B 员工姓名和延期原因。组织架构调整或权限撤销后，不能靠历史审批身份继续读申请。

经理直接改日期或同意延期时，如果新完成日期晚于 B 对 A 的承诺，页面提示「将推迟承诺，保存后会通知对方部门」。必须同时填「新的承诺完成日期」和「给对方部门的说明」；新承诺不能早于各项进行中分配的完成日期，说明不能含 B 员工个人信息。

推迟对外承诺须由有权代表 B 的经理或管理员确认。没有确认权时，延期卡在提交前显示上级确认人的姓名：由上级确认人直接在「协同 → 待审批」代审确认，或者选择「退回」，请员工把完成日期改到承诺日期之内再申请。上级代审提交后，原审批人会收到代审结果通知。确认人姓名只给有权查看的 B 方审批人，不给 A 方。内部日期、新承诺、时间线和通知同时保存，A 方在需求时间线查看「承诺日期变更」及新日期。

### 团队负荷与负荷调整申请

「团队负荷」按部门、姓名展示本周起 8 周，可用「部门筛选」；接口支持选 1–26 周。表格依次显示「姓名」「部门」「Jira 参考值」「上次确认」、各周（`MM/DD 周`）和「操作」。Jira 参考值是未完成指派任务**件数**，不换算成负荷百分比；没有关联 Jira 显示「无」。周格的占用包含该周平台外其他工作、进行中分配和有效预占，显示 `X% / Y%`（占用 / 可用）。有权查看的预占会列出比例和到期时间。可用比例按周一至周五未被不可用日期覆盖的天数计算；部分重叠的分配按整周计。周格还可能显示「修正待审」「可用 X%」「开始日期未确认」。负荷不是绩效，不打分、不排名。

网页或飞书的员工／经理助手可以按姓名读取你有权管辖的员工周负荷，例如「查一下研发部林晓下周的周负荷」。遇到同名时补充部门；管辖外或未找到的人统一提示「不在你的管辖范围或没有找到这个人」。此操作只查询。

| 周状态 | 含义与处理 |
| --- | --- |
| 未确认 | 该周没有经理确认的其他工作占比，不能当成 0% 或「有余量」；做新承诺前先设置 |
| 需重新确认 | 该周上次确认已超过 28 天；先重新确认，旧数不能用于新承诺 |
| 已确认 | 该周的占用与可用可用于分配校验；即使占用已超额，仍如实显示，不自动改分配 |

升级后，旧负荷只会进入原确认时间所在的一周。若「上次确认」有值，可点「沿用上次确认值确认未来 4 周」，一次给当前筛选范围内有上次确认值的员工确认本周起 4 周，最多 200 人；没有上次确认值的人不会选入，须先逐人设置。单人在「操作」点「设置」，打开「设置周投入 · 姓名」，选择「开始周」「结束周」（均为周一，1–26 周），填写「其他工作占比（%）」（0–200 整数）并点「确认设置」。这里填平台外工作，平台内分配另行计入；例如其他工作 40% 加平台分配 30%，占用为 70%。改后通知本人，经理不能直接设置自己；管理员身份本身不授予设置权限。

「操作」中的「不可用日期」打开该员工的登记弹窗。填「开始日期」「结束日期」（最多 92 天，不填原因），点「登记」，已有条目可点「删除」。若登记后已有分配超出当周可用，页面提示「这几周已有分配超出可用，请和部门经理沟通：…」；登记不会自动调整已有分配。经理须有该员工的管辖授权，不能以管理员身份给自己登记。

员工的按周调整申请在「需求与容量 → 待我审批 → 待处理的调整申请」里，先核对开始周、结束周、申请值和原因，再点「同意」或填写处理说明后「退回」。同意后把申请范围内的其他工作占比更新并通知本人；退回不改负荷，员工可重新申请。每人同时最多一条待处理申请。旧的无周范围待审申请获批时只作用于批准当周。负荷调整和延期的代理卡在标题下标明「代某某审批」及原审批人；飞书审批提醒附网页入口，正文不含姓名、日期或申请内容。

负荷申请沿用已有审批路由：有部门授权的直属上级优先，否则沿部门向上找经理，再由管理员兜底，主审批人的全部组织上级可自动代审但不能自批。自动代审按组织架构实时计算，无需在设置页手动授权；纯汇报线上级和兜底管理员也可在「需求与容量 → 待我审批」处理服务端允许审批的申请，不会因此获得团队设置权限。延期另有上文的 B 部门限制。

本人负荷与延期申请也可以在网页／飞书助手发起；内置助手写操作必须点确认卡。批准、分配、直接设置和改日期仍在网页做，模型不可用时表单照常使用。外部 MCP 入口默认关闭。

## 我的团队上方的画像覆盖率

「我的团队」（`/employees`）上方显示「画像覆盖率」，统计当前可见范围内的在职员工：已发布、存在争议、待本人过目、待审批、未知的人数与占比。它按每人的当前审核状态归类，每人只计一类，并非能力项数或能力高低评分；有已发布版本的人也可能因新请求计入待本人过目或待审批。

下方同时显示「初始画像超期未过目」和「等待审批超过 7 天」的请求数。过目期限按企业审批规则，不是固定十四天；请求数不等于员工人数。经理看不到企业 Jira 同步失败信息。

展开「按部门查看（仅本部门在职员工，不含下级汇总）」可比较各部门人数和状态。点部门按钮筛选下方名单，点「全部可见部门」恢复名单；上方总数仍是全部可见范围。未分配部门的员工计入总人数，不会单列部门。

## 导出已发布画像

在「找人」页点「导出已发布画像（CSV）」或「导出已发布画像（JSON）」。导出本人可见范围内全部在职员工的已发布判断，**不受当前页面筛选或分页影响**。离职员工、没有已发布判断的员工，以及当前词典已移除的能力不导出。

每行一条判断，包含工号、能力 key 和名称、等级、判断状态、有效证据数、最近证据时间、批准人和批准时间；未定级判断也会导出。不含陈述、证据标题、原文、依据说明或受限正文。没有结果时 CSV 只有表头，JSON 为 `[]`。

每次成功下载会写导出审计。文件应按企业数据管理要求保管；CSV 使用 UTF-8 BOM，导入 Excel 时将工号设为文本以保留前导零。字段、特殊工号处理及登录后接口见[已发布画像导出说明](profile-export.md)。该接口只读，不会写回 HR 系统，MCP 没有导出工具。

## 直接修改下属画像

在下属能力卡点「直接修改」，填写陈述和等级，点「预览修改」，核对前后差异后点「确认直接发布」。也可以添加能力或撤回判断。发布无需本人同意，也不走待审批；新增和修改为已确认，撤回后为未知。员工会收到站内通知，已开启飞书推送且绑定时同时收到飞书消息。

在网页助手或飞书私聊可要求列出团队、查看下属画像并整理修改，核对确认卡后点「确认修改」才发布。不能直接改自己、其他企业、范围外或离职员工；同时具有管理员身份时，员工助手仍按管辖范围处理，全企业管理须用管理助手。不能改企业设置、能力词典或部门对应能力。

画像在预览后变化会提示刷新，读取新内容后重新修改。员工对直接修改有异议时重新编辑并提交审批；已有待审请求若引用的判断被取代，需要重提。直接修改不改写证据，改前改后和操作者留在审计中。

尚待本人过目的旧初稿可以继续处理：即使员工直接点提交，也会先展示当前正式值及按企业时区显示的直接修改时间，重新核对后才能送审。员工可移除旧稿项，或修改后重新预览，仍须按企业规则审批。陈述 200 字、各项说明 4000 字、每次 50 条的上限见[员工指南](employee-guide.md#每次改动的输入上限)。

## 逐项决定

1. 查看改动前后、等级、陈述、证据、解释和不确定之处；请求中的长陈述可展开。「只有 Jira 来源」批准后仍为暂定，不能据 assignee 推断员工独立完成工作（管理员配置「无需审批」且由智能起草自动发布的除外）。
2. 每项选择「批准」或「拒绝」。拒绝必须写原因；可留整体意见。
3. 点「核对并提交」，检查复述的逐项决定，再点「确认提交决定」。内容变化时重新加载核对。

批准项在同一事务中生成新判断与画像版本。部分批准立即发布，拒绝项会退回并另建员工重提草稿；请求卡按逐项结果汇总，如「1 项批准、2 项被拒绝」，助手与通知也统一显示为「被拒绝」。意见作为受限经理评价证据保留。平台已取消被拒申诉流程：员工可在「已处理请求」或能力卡详情查看「提交被拒绝」与拒绝原因，在「已处理请求」点击「修改重提」（或到「其他待处理请求」继续修改草稿）重新提交；系统升级前遗留的历史申诉记录仅作只读展示，争议标记不改写旧判断。

提交决定后，该请求会立即从待审批列表移除，可返回列表打开下一条；已处理或无权审批的详情会说明原因并提供返回入口。员工的提交预览和待审批请求中显示当前审批人及身份，代理人和原审批人可同时列出。

审批详情显示「分配原因」：直属上级同时是管辖部门经理时优先交给他，否则找本部门或上级部门经理，都没有时交企业管理员。有效代理显示代谁审批及原审批人的分配原因；这些说明不改变审批权限。

值班经理即使是直属上级，没有部门经理授权也不会因此得到团队查看或审批权。「设置 → 个人信息」会列出本人无权审批的直属下属及当前审批人；助手和飞书也会解释去向，需要授权请找企业管理员。本人已经有该下属审批权时不显示这段提示，选人规则不变。

当前获授权审批人（含自动上级代审人、兜底管理员）在待审批期间可读请求引用的证据原文，不扩大到其他员工。具备日常管辖权的经理仍可按日常范围查看员工画像中与该证据关联的判断；仅凭待审批请求获得临时读取权限的跨部门汇报线上级，在审批页和证据详情页仅可查看本单送审能力与该证据的关联，不会看到同一证据关联的其他能力项。请求审批完成、撤回，或汇报线、部门授权、角色与账号状态变更回收权限后，临时读取权限立即失效并恢复原有可见范围；非管辖汇报线上级不会因此获得对方整个部门的访问权。

## 代理审批

代理审批已改为按组织架构自动设置，随汇报线与部门层级实时同步，无需手动添加或撤销。当你作为主审批人时，你的全层级汇报线上级与严格上级部门经理均可直接在「协同 → 待审批」（及机器人入口）代为审批，先提交的决定生效。新提交请求仅通知主审批人本人，避免向全部隔级上级群发；当上级实际代审后，系统会向原审批人发送站内通知。任何人都不能借代理批准自己的请求。在「设置 → 偏好与代理 → 代理审批」可只读查看当前可代审你的全部上级及其组织关系。

## 在网页助手审批

可以问「有什么要我批的」，若你明确针对单条无歧义请求指令「批准」（或给出原因指令「拒绝」），网页助手会直接调用审批接口提交结果并写入审计，同时排除自批；若涉及多条、批量或指代不清的请求，仍生成「审批决定复述」卡供你核对后点「确认决定」。点「去审批页查看证据」可读本次审批有权查看的依据，助手卡不展示受限正文。直接修改员工画像或团队工作量仍需通过确认卡二次确认；内容变化时重新读取。网页助手记来源为网页，批准与发布在同一事务内完成。

## 用内置助手或 IM 审批

经理可在「待审批」、网页内置助手与飞书 IM 中读取待审批请求、核对变更与依据后确认提交审批；审批与发布在同一事务内完成，任何人都不能批准自己的请求。历史上通过外部接入提交的记录仍保留只读来源标签。外部 MCP 审批入口默认关闭（`EXTERNAL_MCP_ENABLED=false`）。

飞书、企业微信、Telegram 需先绑定。私聊问「有什么要我批的」；明确指令单条无歧义请求「批准」（或带原因「拒绝」）时助手直接提交并回复结果，若涉及多条/指代不明或逐项混合决定，则生成审批复述卡片后点「确认决定」。需要改动时点「继续修改」，卡片过长或需读受限原文时进入网页。记录来源为对应客户端名称（飞书 / 企业微信 / Telegram）。

三个 IM 平台目前仅以假服务验证，真实权限、可见范围及卡片显示由管理员试运行核实。

## 组织架构

从导航栏「组织架构」进入只读架构图，查看授权部门及下级的层级连线、经理和人数，可折叠下级部门。点部门查看汇报树，点人员查看上级链、本人和直接下属；「查看详情」进入员工详情，面包屑返回部门层级。汇报环显示「汇报线有循环」，大图可横向和纵向滚动。范围由服务器按当前授权计算。代审权限只临时用于当前请求，不会扩大架构图范围。

部门改名、移动和删除由企业管理员操作，经理页面不显示编辑按钮。移动部门后，原上级和新上级经理的管辖范围按新层级立即重算，继承的对应能力也会变化；移动子树内已有的直接部门经理授权保留。
